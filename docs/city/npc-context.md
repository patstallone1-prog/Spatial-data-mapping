# NPC context for dialogue

`City.characterContext(person, cityTime, world)` returns either a ready context or a pending result with a `ready` promise. Wait for the promise and retry when it resolves true. `NpcContextIndex` prepares profiles in small background chunks, caches the index by roster/day, and reads current finances, incidents and routes when a character is requested. No model/API call runs in the rendering loop.

Every character uses the same versioned keys: `identity`, `tone`, `group`, `finances`, `history`, `job`, `hobbies`, and `travel`. Money is integer minor units of the simulation's currency (`KCR`, currently Credits at USD parity), never an ambiguous decimal dollar amount. Unknown finance/history/itineraries are null, with explicit availability for the balance; they are not invented zeroes. Financial books include the simulation's recent transaction lines, income, costs and assets. The latest eight recorded incidents are included alongside career history and the actual day's route legs and transport modes.

Cohorts target 8–12 members, favoring exact job role, occupational family, balance band, and tone family. Sparse occupational remainders are pooled to achieve viable sizes where possible. Populations that cannot be partitioned into 8–12, or retained cohorts temporarily missing members, are explicitly marked `undersized`. This flag should not be presented as a character trait. Existing cohorts reserve members absent from a partly loaded district, and save their IDs, shared stories and profile signatures in the roster. Significant career/status/balance changes can move a character to a new cohort with a recorded transition.

Each cohort has an authored fictional two-sentence biography. Every member receives exactly the same story; individual voice variants, two hobbies, live bank balance, debts, career and route context remain independent. Stories describe formative experiences rather than claiming an invented job or financial transaction. `source: authored` distinguishes creative story/voice/hobby data from simulation records. Do not use the shared biography to override individual state: a person with no job cannot truthfully claim to be on shift, and an unavailable balance cannot be asserted as known.

The People inspector displays the shared story and individual voice/interests, with an expandable JSON snapshot for dialogue consumers. This change supplies context; it does not introduce a paid dialogue service or silently send character/world data to an external model.
